# Pith v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Pith v1. It is a free macOS menu-bar app: a calm dot plus one minimal panel that shows which apps use memory, CPU and disk, with each app's helpers grouped into one row. It must be light, exact and pristine.

**Architecture:** A Swift package with two targets.
- `PithCore` holds pure, unit-tested logic and macOS readers: libproc, Mach host APIs and sysctl.
- `Pith` is an AppKit status item and non-activating `NSPanel` hosting SwiftUI views.

One `Clock` drives one `Engine` actor. The engine returns an immutable `Snapshot` per tick. `StatusRules` turns it into the dot and the sentence, and the UI only draws snapshots.

**Tech Stack:** Swift 6 (language mode 6, strict concurrency), SwiftPM, AppKit, SwiftUI, Swift Testing, bash scripts. Zero third-party dependencies.

**Spec:** `docs/specs/2026-10-25-pith-design.md`. Visual references: `docs/specs/pith-design-1-what-you-see.html` and `docs/specs/pith-design-2-how-it-works.html`.

## Global Constraints

- **Where work runs:** all work runs on the Mac mini in `~/Codex/Projects/Pith`. Run the session there, through `ssh mini`, a T3 Mac mini environment, or a session started on the mini.
- **Toolchain:** Command Line Tools only, no Xcode. `swift-tools-version: 6.0`, platforms `.macOS(.v15)`, Swift language mode 6, Apple Silicon (`arm64`) only.
- **Identity:** bundle ID `com.mrinoy.pith`, app name `Pith`, `LSUIElement = YES`, `LSMinimumSystemVersion = 15.0`.
- **Dependencies:** zero third-party packages. No widget extension, no XPC service, no helper tool.
- **Resource use:** Pith makes **no network calls**. It launches no child process except the on-demand `/usr/bin/top` (spec 6.7). It writes to disk only settings and the pinned panel frame.
- **Unknown values:** a missing reading is `Reading.unavailable(reason)`, shown as "Not available" or "—". It is never shown as 0.
- **UI:**
  - text the user must read is at least 13 pt, in SF Pro, with tabular numerals for all values;
  - color appears only for state: `NSColor.systemOrange` for Tight and `NSColor.systemRed` for Critical;
  - the panel is 360 pt wide.
- **Copy:** UI strings are copied exactly from spec sections 4 and 7.3.
- **Public repo:** fixtures, screenshots and README images use **synthetic data only**, with no real process lists, paths or user names.
- **Ported Stats code:** each adapted file starts with a header like this:

  ```swift

  // Copyright (c) 2020 Serhiy Mytrovtsiy. Source: Modules/RAM/readers.swift L37-L103 at v3.0.22 (1282cd5).
  ```

- **Testing launches:** final checks launch the installed app with `open /Applications/Pith.app`, never a `.build` binary (spec 12).
- **Commits:** every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Run `./scripts/ci-local.sh` before every push.
- **PRs:** three PRs: core (Tasks 1–9), app (Tasks 10–13) and tooling (Tasks 14–16).
  - Each PR body follows `~/Codex/Tooling/Fleet/docs/pr-body-template.md` ("At a glance", before/after visuals).
  - Each PR gets `/cr`, then the council, before merge.
  - Pull request descriptions end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

## Review Focus

1. **A very large process table** (the Pro has an M5 Max and 128 GB, and can run more than 1,500 processes). The table read must grow its PID buffer and never drop processes. The test is in Task 3.
2. **A process exits between listing and reading** (`ESRCH` from `proc_pid_rusage`). It is counted in `vanished` and left out, with no assert and no error row. The test is in Task 3.
3. **Wake from sleep, or the panel reopens after minutes closed.** The first tick after `resetBaseline()` must show "—" for CPU and Disk, never a spike from a stale baseline. The test is in Task 9.
4. **Two apps with the same name, or an app outside `/Applications`** (for example `~/Applications/X.app` or `/Volumes/DMG/X.app`). Groups are keyed by bundle path, so they never merge. The test is in Task 4.
5. **Panel placement on a secondary display, near a screen edge, or over a full-screen app.** The panel frame must stay inside the visible frame of the status item's screen. The test is in Task 10.
